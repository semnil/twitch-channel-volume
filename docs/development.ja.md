# 開発メモ

> For the English version, see [development.md](development.md).

コードを触るときのメモ。保存の形と、以前の版が残した項目の扱い、popup が定期的に読むもの、`[TCV]` のログからの調べ方を書く。何を走らせるか、何に触らないかのメモは、`AGENTS.md` の「Development notes」にある。

- AudioContext は、ページが操作されるまで `suspended` で始まる (Chrome の自動再生のポリシー)。回復のしかたは [design.ja.md](design.ja.md) の「AudioContext が止まっているとき」にある
- BS.1770 の基準は 48 kHz。Chrome の AudioContext はふつう 48000 で、サンプルレートが違うときは redesignBiquad (`core/loudness.js`) が扱う
- 保存キー: `autoLoudnessSettings` (Target LUFS、CM ゲイン、表示の単位、種別ごとの Auto の既定値。`chrome.storage.sync` に置き、ほかは `chrome.storage.local` に置く)、`channelVolumes` (チャンネルごとの保存したゲイン + 種別ごとの Auto + lastLufs のキャッシュとその窓の数)、`channelVolumeAliases` (仮 ID → 正規の ID)、`channelVolumeSequence` (消えない更新の番号)
- 保存の形: `channelVolumes.{id}` = `{ name, login, gainLive, gainVod, autoGainLive, autoGainVod, autoApplyLoudnessLive, autoApplyLoudnessVod, url, lastLufs: { live, vod }, lastLufsRef: { live, vod }, lastLufsWindows: { live, vod }, lastLufsClearedAt: { live, vod }, autoGainRef: { live, vod }, lastMeasuredAt, __fieldVersions }`
- 以前の版が残したクリップの項目 (`gainClip`、`autoGainClip`、`autoApplyLoudnessClip`、`lastLufs` / `lastLufsRef` / `lastLufsWindows` / `autoGainRef` の `clip` のキー、それらの `__fieldVersions` の項目) は、channel-store.js が次に書くときに `withoutClipFields` が落とす。`lastMeasuredAt` は、行の最後の `lastLufs` の値と一緒に消える。これで値を 1 つも持たなくなった行 (ゲインも、Auto の選択も、計測値も、古い形の `gain` / `autoApplyLoudness` も無く、name・login・URL だけの行) は、クリップだけのための行だったので、一緒に消す。この処理が走る前から何も持っていなかった行には触らない。`clip-owner:<slug>` の別名が指す先にも触らない
- 古い形の単一の項目は、channel-store.js が書くときに展開して消す (`gain` → `expandLegacyGain`、`autoApplyLoudness` → `expandLegacyAutoFlag`。どちらも core/common.js。自分の Auto のフラグを持つ種別は、それを保つ)。読む側の `extractGainForKind` は、展開する前の項目を読むための代わりの手段で、何も書き戻さない
- popup は、`STATE_POLL_INTERVAL_MS` ごとに getState を読み (core/common.js の `pollTabState`)、LUFS / Suggested / Current のカードを更新する。Auto のゲインは、`AUTO_FOLLOW_INTERVAL_MS` (1 秒) に多くても 1 回更新される。Manual のスライダーが今かかっているゲインに合わせるのは、Auto がオンの間と、ブラウザがドラッグを取り消した後から次の操作が始まるまでの間だけ。Auto がオフのときの通常の定期的な読み取りは、スライダーに触らない。Auto がオフのときに合わせるのは、最初の表示、「チャンネルに適用」、Auto の切り替え、表示の単位の変更、利用者の入力のとき。計測そのものは popup が開いているかどうかに関係なく、Twitch のページが開いている間ずっと走る
- 拡張機能の読み直しで chrome.runtime が無効になったとき、popup は `reloadPageNeeded` を出して F5 を頼む。設定の読み取りに失敗した popup もこれを出し、タブには何も問い合わせない
- 計測の流れを調べる: DevTools の Console で `[TCV]` のログを読む。出る順番は、`waiting for <video>` → `attached to video` → `measurement chain ready` → `first measurement block received`。`media served from another origin without CORS; the element keeps the player audio path` は、その要素を飛ばしたことを言う (`ad: true` は CM の経路の印。この経路は content.js に何も知らせないので、この経路ではこの行がただ 1 つの記録になる)。`player audio unavailable` は、content.js が、受け取った原因を名指ししている行。`createMediaElementSource failed` で止まるのは、別の拡張機能とのぶつかり (技術的な制限)。この状態は、popup の知らせと、`getState` の audioUnavailable に出る。その後のやり直しでは `no attachable <video>; the player audio is held elsewhere` が出る (`waiting for <video>` が出るのは、要素そのものが無いときだけ)。`audio context unavailable` / `audio context resume failed` / `audio context stayed <state> after resume` も、同じ経路を調べるためのもの。context が動くまでは、操作のたびに resume を頼むので、最後の行は、操作ごとではなく、context が断り続けているひと続きの間に 1 回だけ出る
- CM の境界と音量の変化を調べる: Console で次を追う。`[TCV] ad detected in DOM` (DOM での検出と `video.currentTime`)、`[TCV] ad cue from the player` (cue の `rollType`、メディアの時刻で表した区間、届いたときの再生位置、CM 枠の中での位置)、`[TCV] ad element attached` (CM 要素をつないだときの、その要素の音量と本編の音量)、`[TCV] gate boundary` / `[TCV] gate resumed` (境界の理由、volume、muted、再生位置、外した窓の数、直近 4 窓の LUFS)、`[TCV] ad start rollback` (頼まれた窓の数、境界のスキップと重なったために引いた数、取り消した数とそれぞれの LUFS。`exhausted` は、頼まれた数の窓をさかのぼれたかどうかを言い、false は、計測の始まりが近く、そこで範囲が止まったことを指す)。別の理由で途中で切られたスキップは、そこまでに外した数を、次の `gate boundary` の `superseded` / `droppedBefore` に持ち越す
- 失敗した操作を調べる: 失敗は、それが起きた画面に、名前を付けて残す。ページの側 (Twitch のタブの Console) には、`[TCV] failed to save gain` (保存しようとしたチャンネルを名指しする。遷移の後に画面に出ているチャンネルではない) / `[TCV] failed to save Auto setting` / `[TCV] failed to reset measurement` がある。計測が自分で行う保存については、失敗のひと続きが始まったところで `[TCV] measurement not persisted`、そのひと続きが 5 秒続いたところで `[TCV] failed to persist measurement and Auto gain` が出る。ブロックは 1 秒に 10 回届き、失敗した保存を繰り返す。そのため、ひと続きは各レベルで 1 回だけ名指しし、保存が 1 回通ればひと続きは終わる。拡張機能がもう動いていないページに届いた reject は、どこにも名指しされない。このほかに、最後の受け皿のハンドラーの `[TCV] failed to handle a bridge message` / `[TCV] failed to handle a route change` / `[TCV] failed to start up` / `[TCV] unknown command` がある。popup の側 (popup の DevTools) には、`[TCV] suggested gain request failed` / `[TCV] gain request failed` / `[TCV] Auto setting request failed` / `[TCV] measurement reset request failed` があり、content.js が返した理由を持つ。`[TCV] state request failed` は、`getState` がそもそも届かなかった理由を持つ。問い合わせる Twitch のタブが無い (manifest は twitch.tv だけを求め、tabs の権限を求めないので、Chrome はほかのタブの URL をすべて渡さない)、またはそこに答えるものがいない (拡張機能より前に開いたページ、無くなったタブ、読み直しで無効になった runtime)。前者は info で、後者は warn でログに出す。Chrome は popup の warn を拡張機能のエラーとして集める。そして、別のサイトの上で開いた popup や、タブが Twitch から離れる間も開いたままの popup には、視聴者が直せることが何も無い。表示は 1 秒ごとに読み直すので、この行は、失敗が続くひと続きについて 1 回、そして次の要求が届いたらもう 1 回名指しする。自分の失敗の後で状態を読み直す 4 つの呼び出し元のうち、`catch` の中にある 2 つは、状態の行を求めず、次の定期的な読み取りが画面全体を取るまで、自分が出したメッセージを保つ。`applyMeasured` と `setGain` は、状態の行ありで読み直す。そのため、まったく答えられないページでは、この 2 つ自身のメッセージは描かれない (メッセージを書くのは `renderState` で、状態を受け取れなかったときはそこで戻るため)。options の側 (設定ページの DevTools) には、`[TCV] failed to delete the channel` / `[TCV] failed to clear the saved channels` がある。Service Worker の側 (拡張機能の Service Worker の DevTools) には、`[TCV] channelVolumes mutation failed` / `[TCV] settings mutation failed` (storage から)、`[TCV] channelVolumes mutation rejected as invalid` / `[TCV] settings mutation rejected as invalid` (呼び出し側の入力)、`[TCV] channelVolumes mutation blocked by the stored state` / `[TCV] settings mutation blocked by the stored state` (保存されている状態)、`[TCV] failed to move the settings to sync` (worker の起動のときの移し替え。設定は local に残り、読み手はそこで見つけられる。次の起動でもう一度試す)、`[TCV] unknown message type` がある
