# Error-list decisions

> For the English version, see [error-list.md](error-list.md).

Chrome が拡張機能ごとに持つエラーの一覧に、何が載るかについて閉じた判断。今有効な規則は、`docs/design.ja.md` の「だれも処理しないページの fetch」と、`docs/development.ja.md` の「失敗した操作を調べる」にある。

## The Worker wrapper carries no suppression

- **決定** (2026-09-13): `page-bridge.js` の `Worker` の包みには、失敗した `new Worker` を拡張機能のエラー一覧から外す処理を入れない。包みを通って例外を投げたコンストラクタは、包みが無いときと同じようにページへ例外を投げる。
- **理由**: 包みを通って投げられたエラーは `page-bridge.js` の行を持つので、自分のエラーの既定の動作を止めないページでは、Chrome がそれを拡張機能のエラーとして記録する。この決定は、twitch.tv がその既定の動作を自分で止めることに頼っていて、そこでは一覧に載らない。判断の材料にした失敗は、読み込めないスクリプトの URL をコンストラクタに渡してわざと起こしたもので、普段の視聴で起きることを示すものは無い。fetch の包みの隣の `unhandledrejection` リスナーは、サイトが既定の動作を止めなくなったときの保険として入れた。Worker の包みには、その保険を掛けない。
- **覆す条件**: 実際の Twitch のページで、包みを通って失敗した `new Worker` の既定の動作をページが止めていないと分かったとき。または、Worker の失敗が拡張機能のエラー一覧に載ったという報告があったとき。この場面を起こした probe (ページに当てて挙動を見るためのスクリプト) はもう無いので、1 つ目を確かめるには、同じ場面を起こすものを作り直して実際のページに当てる。

## The one "Receiving end does not exist" report stays unexplained

- **決定** (2026-11-14): 計測の保存から上がった `Could not establish connection. Receiving end does not exist.` の報告 1 件は、引き金を特定しないまま置き、これ以上は何も変えない。この報告には、[#66](https://github.com/semnil/twitch-channel-volume/pull/66) が、次のブロックで消える失敗をエラー一覧に載せない形で答えている。
- **理由**: この文言は、送った先に `onMessage` のリスナーが無いときに出る。#66 がこの文言を出せたのは、その形 (入っていない拡張機能の id へ送る、リスナーを登録しない worker へ送る) だけだった。#66 が試したライフサイクルの出来事では、送信が解決するか、別の文言になった。#66 が眠るマシンの代わりにしたのは、Chrome の全プロセスを止めて再開する走行だった。その後、2026-11-14 に実際のスリープを見た: 配信中のチャンネルのページを開き、拡張機能が動いている状態で、Mac を 5 分ほど眠らせた。戻った後、拡張機能のエラー一覧に増えた行は無く、ページのコンソールにも拡張機能の行は無かった。そこにあった行は、Twitch のプレイヤー (眠っている間の fetch の失敗と、その後の再生の再開) と、ページ自身のものだった。
- **覆す条件**: この文言がもう一度報告されたとき (エラー一覧の、その行の発生回数とスタックを読む)。または、スリープから戻った後に、拡張機能のエラー一覧に行が増えたとき。
