# Development notes

> 日本語版は [development.ja.md](development.ja.md) を参照してください.

Notes for working on the code: the stored format and what is done with the fields an earlier version left, what the popup polls, and how to diagnose from the `[TCV]` logs. The notes that say what to run and what to leave alone are in `AGENTS.md`, "Development notes".

- AudioContext starts `suspended` until the page has been interacted with (Chrome autoplay policy). The recovery is in [design.md](design.md), "When the AudioContext is suspended"
- BS.1770 reference is 48 kHz. Chrome's AudioContext is normally 48000, and a varying sample rate is handled by redesignBiquad (`core/loudness.js`)
- Storage keys: `autoLoudnessSettings` (target LUFS, ad gain, display unit, per-kind Auto defaults; in `chrome.storage.sync`, the rest in `chrome.storage.local`), `channelVolumes` (per-channel saved gains + per-kind Auto + the lastLufs cache and its window count), `channelVolumeAliases` (provisional ID → canonical ID), `channelVolumeSequence` (persistent update number)
- Storage format: `channelVolumes.{id}` = `{ name, login, gainLive, gainVod, autoGainLive, autoGainVod, autoApplyLoudnessLive, autoApplyLoudnessVod, url, lastLufs: { live, vod }, lastLufsRef: { live, vod }, lastLufsWindows: { live, vod }, lastLufsClearedAt: { live, vod }, autoGainRef: { live, vod }, lastMeasuredAt, __fieldVersions }`
- A clip field left by an earlier version (`gainClip`, `autoGainClip`, `autoApplyLoudnessClip`, the `clip` key of `lastLufs` / `lastLufsRef` / `lastLufsWindows` / `autoGainRef`, and their `__fieldVersions` entries) is dropped by `withoutClipFields` the next time channel-store.js writes. `lastMeasuredAt` goes with the last `lastLufs` value on the row. A row this leaves holding no value at all — no gain, no Auto choice, no measurement, no legacy `gain` / `autoApplyLoudness`, only the name, login and URL — was a row for the clip alone and is deleted with it. A row that already held nothing before this ran is not touched by it, and neither is the `clip-owner:<slug>` alias's target
- The legacy single fields are expanded and deleted by channel-store.js at write time (`gain` → `expandLegacyGain`, `autoApplyLoudness` → `expandLegacyAutoFlag`, both in core/common.js; a kind with an Auto flag of its own keeps it). On the read side, `extractGainForKind` is a fallback for reading an entry before expansion, and writes nothing back
- The popup polls getState every `STATE_POLL_INTERVAL_MS` (`pollTabState` in core/common.js) and updates the LUFS / Suggested / Current cards. The Auto gain updates at most once per `AUTO_FOLLOW_INTERVAL_MS` (1 s). The Manual slider syncs to the gain in force only while Auto is on, and after a drag the browser cancelled until the next gesture begins; the ordinary polling with Auto off leaves it alone. With Auto off it syncs on the first display, on "Apply to channel", on an Auto toggle, on a display-unit change and on user input. The measurement itself does not depend on the popup being open, and runs for as long as a Twitch page is open
- When reloading the extension invalidates chrome.runtime, the popup shows `reloadPageNeeded` and asks for F5. A popup whose read of the settings fails shows it as well, and asks the tab nothing
- Diagnosing the measurement pipeline: read the `[TCV]` logs in the DevTools Console. They appear in the order `waiting for <video>` → `attached to video` → `measurement chain ready` → `first measurement block received`. `media served from another origin without CORS; the element keeps the player audio path` says the element was passed over (`ad: true` marks the ad path, which reports nothing to content.js, so on that path this line is the only record), and `player audio unavailable` is content.js naming the cause it was given. Stopping at `createMediaElementSource failed` is a conflict with another extension (a technical limit). That state surfaces in the popup notice and in `getState`'s audioUnavailable. Later retries print `no attachable <video>; the player audio is held elsewhere` (`waiting for <video>` appears only when the element itself is absent). `audio context unavailable` / `audio context resume failed` / `audio context stayed <state> after resume` diagnose the same path. Every gesture asks for a resume until the context runs, so the last of those is printed once per stretch the context spends refusing rather than once per gesture
- Diagnosing ad boundaries and volume changes: follow these in the Console — `[TCV] ad detected in DOM` (the DOM detection and `video.currentTime`), `[TCV] ad cue from the player` (the cue's `rollType`, the span in media time, the playback position when it arrived, the position within the pod), `[TCV] ad element attached` (that element's volume and the main volume when the ad element was connected), `[TCV] gate boundary` / `[TCV] gate resumed` (the reason for the boundary, volume, muted, playback position, the number of windows excluded and the LUFS of the last 4 windows), `[TCV] ad start rollback` (the number of windows requested, the number subtracted for overlapping the boundary skip, the number withdrawn and the LUFS of each — `exhausted` says whether the requested number of windows could be walked back, and false means the start of measurement is near and the span stops there). A skip cut short for another reason carries its exclusion count up to that point into `superseded` / `droppedBefore` on the next `gate boundary`
- Diagnosing a failed action: a failure is left named, on the screen it happened on. The page side (the Console of the Twitch tab) has `[TCV] failed to save gain` (which names the channel it tried to save, not the one on screen after a navigation) / `[TCV] failed to save Auto setting` / `[TCV] failed to reset measurement`, and, for the save the measurement makes by itself, `[TCV] measurement not persisted` where a stretch of failures starts and `[TCV] failed to persist measurement and Auto gain` once that stretch has lasted five seconds. A block arrives ten times a second and repeats a failed save, so the stretch is named once at each level and a save that gets through ends it; a rejection that reaches a page the extension no longer runs in is named nowhere. Plus the terminal handlers' `[TCV] failed to handle a bridge message` / `[TCV] failed to handle a route change` / `[TCV] failed to start up` / `[TCV] unknown command`. The popup side (the popup's DevTools) has `[TCV] suggested gain request failed` / `[TCV] gain request failed` / `[TCV] Auto setting request failed` / `[TCV] measurement reset request failed`, carrying the reason content.js returned, and `[TCV] state request failed`, carrying the reason `getState` did not arrive at all: no Twitch tab to ask (the manifest asks for twitch.tv alone and for no tabs permission, so Chrome withholds every other tab's URL), or nothing there to answer (a page opened before the extension, a tab that has gone, a runtime the reload invalidated). The first is logged at info and the others at warn: Chrome collects the popup's warnings as extension errors, and a popup opened over another site, or left open while its tab navigates away from Twitch, has nothing for the viewer to put right. The display polls every second, so that one is named once for the stretch the failure lasts and again once the next request arrives. Of the four callers that re-read the state after a failure of their own, the two inside a `catch` ask for no status line and keep the message they put up until the next poll takes the whole screen; `applyMeasured` and `setGain` re-read with the status line on, and on a page that cannot answer at all their own message is never drawn (it is written by `renderState`, which returns on the state it did not get). The options side (the settings page's DevTools) has `[TCV] failed to delete the channel` / `[TCV] failed to clear the saved channels`. The Service Worker side (the extension's Service Worker DevTools) has `[TCV] channelVolumes mutation failed` / `[TCV] settings mutation failed` (from storage), `[TCV] channelVolumes mutation rejected as invalid` / `[TCV] settings mutation rejected as invalid` (the caller's input), `[TCV] channelVolumes mutation blocked by the stored state` / `[TCV] settings mutation blocked by the stored state` (the stored state), `[TCV] failed to move the settings to sync` (the move at worker start; the settings stay in local, where the readers still find them, and the next start tries again), and `[TCV] unknown message type`
